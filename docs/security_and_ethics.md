## 3. AI ethics

| # | หลักการ | สถานะ | ทำอย่างไร |
| --- | --- | --- | --- |
| E1 | ความปลอดภัยทางคลินิก | 🟡 | คำตอบต้องมีข้อความ "เพื่อการศึกษา ไม่ใช่คำแนะนำทางการแพทย์รายบุคคล"; ไม่ตอบคำถามวินิจฉัย/ปรับยารายบุคคล; หลักฐานไม่พอให้เว้นตอบ (Track B plan §13, D) |
| E2 | ความถูกต้องของข้อมูล | ✅/🟡 | ทุกหน้า OCR มีผลตรวจและวิธีตรวจใน `human_review`; ตัวเลข/เครื่องหมาย/ชื่อยาถูกตรวจเทียบภาพ (เช่น ≥ 126, Insulatard); ยังเหลือหน้า PDF-text ปกติที่ไม่ได้ตรวจเทียบภาพ |
| E3 | Provenance / citation | 🟡 | ทุก chunk ต้องชี้กลับ `document_id` + หน้า PDF; demo ควรแสดงชื่อเอกสาร ฉบับ ปี และลิงก์หน้า/ภาพต้นฉบับ |
| E4 | ความทันสมัยของแนวทาง | ⬜ | แสดงปีของฉบับเสมอ; ฉบับต่างปีที่ขัดกันให้แยกตอบ ไม่รวม |
| E5 | ประชากรเป้าหมาย | 🟡 | เครื่องมือพร้อม: หน้า review แนะนำช่วงจากชื่อบท (DM CPG บทที่ 16–18 ≈ p201–241, หนังสืออาหารทุกวัยของ INMU) และแสดงทุกหน้าที่มีคำเกี่ยวกับเด็ก/ตั้งครรภ์ (41 เอกสาร); คนติดป้าย → ทุกหน้าใน v8 มี `population` ให้ retriever กรองได้ |
| E6 | Bias / ความครอบคลุม | 🟡 | corpus เอียงไปเอกสารบริการของกรมควบคุมโรคและเอกสารผู้ป่วย; LIPID มีแนวทางหลักฉบับเดียว — รายงานเป็นข้อจำกัด และดู recall แยกตามโรคใน evaluation |
| E7 | ลิขสิทธิ์ / การยินยอม | 🟡 | ทีมตัดสินใช้เพื่อการศึกษา (rights queue); **หลักฐานอนุญาตจากศูนย์เบาหวานศิริราช ยังไม่ได้แนบ** — ต้องแนบหรือถอด 9 สื่อนั้นก่อนอ้างผล |
| E8 | ความโปร่งใสเรื่องการใช้ AI | 🟡 | ข้อมูลระบุ `review_method` ทุกหน้า: คนตรวจข้อเสนอ AI 255, AI เทียบภาพ 63, AI ตามความเสี่ยง 36; ต้องสรุปลง AI Audit (Decision Journal / Error Catch) |
| E9 | Human oversight | 🟡 | คนตัดสินทุกหน้าในรอบ v7; หน้าที่ AI ตรวจอย่างเดียว (99 หน้า) ยังมี `human_confirmation: null` — สุ่มยืนยันหรือระบุเป็นข้อจำกัด |
| E10 | ไม่แต่งหลักฐาน | ✅ | กติกา AGENTS.md: ห้ามแต่ง approval, metrics, AI Audit events; ข้อความที่ OCR แต่งขึ้นถูกตัดออก (ภาพบรรยาย `<figure>`, ชื่อ/เมนูที่ไม่มีจริง) |

## 5. รายการที่ต้องทำก่อนส่ง (เรียงตามความเสี่ยง)

1. E1 + S7 + R5–R7: ใส่ guard ใน answer pipeline (ข้อความ disclaimer, input guard ข้อมูลส่วนบุคคล, citation + abstain) และชุดทดสอบ prompt injection (Track D/C)
2. E7: แนบหลักฐานอนุญาตศิริราช หรือถอด 9 สื่อออกจาก corpus version ที่ใช้ประเมิน
3. E5 + S10 + R1–R4: ติดป้ายประชากร ตัดสินข้อมูลส่วนบุคคล/เคสผู้ป่วยในหน้า review แล้วสร้าง v8 ก่อน chunking
4. E8/E9 + ตาราง §2: บันทึกลง `AI_AUDIT.md` (ขั้นตอนละเอียดอยู่ใน [corpus_process_record.md](corpus_process_record.md))
5. S3/S4: rotate keys หลังส่ง และเพิ่ม secret scan ก่อน push
