# โครงสไลด์ 10 แผ่น ตามโจทย์วิชา (ร่างโดย AI; เจ้าของแก้และเป็นผู้นำเสนอ)

โจทย์กำหนด: สไลด์ไม่เกิน 10 แผ่น **ห้ามมีโค้ดบนสไลด์** (ใช้แผนภาพสถาปัตยกรรมและตารางผลเท่านั้น), เวลา 10 นาทีเดโม + 5 นาทีถามตอบ, ต้องอธิบายและแก้ไขได้ทุกการตัดสินใจ ตัวเลขทุกตัวอ้างจาก `runs/` และ `docs/` ในรีโป

| แผ่น | เนื้อหาที่โจทย์ต้องการ | ใส่อะไร (ข้อมูลอยู่ที่ไหน) |
|---|---|---|
| 1 | ชื่อโครงงาน ทีม โดเมน | Thai NCD Guideline Q&A; ชื่อทีม 4 คน (README หัวข้อ 9); โดเมน: แนวทางเวชปฏิบัติ NCD ไทย (เบาหวาน, ความดัน, ไขมัน, ไต) |
| 2 | แรงจูงใจ ทำไมโดเมนนี้ต้องมีระบบ Q&A | เอกสารยาวหลายร้อยหน้า หาตัวเลข/เกณฑ์ยาก; คำตอบต้องอ้างอิงได้และต้องงดตอบเมื่อไม่รู้ (ความเสี่ยงทางการแพทย์); corpus จริง 66 เอกสาร / 3,716 หน้า |
| 3 | แผนภาพสถาปัตยกรรม (pipeline เต็ม) | ใช้แผนภาพใน README หัวข้อ 1: ตัวกรองอินพุต → ค้นคืน hybrid → prompt → LLM → ตรวจ claim → ตัวกรองเอาต์พุต; แสดงตัวแปรที่เทียบ (A/B/C/D, LangGraph, ReAct) |
| 4 | การตัดสินใจหลัก 1: chunking และ embedding | parent-child (child 128 ค้น → parent 512 ส่ง), ไม่ตัดกลางคำ/ตารางแยกเป็นแถว; bge-m3 เทียบ e5-base; ตารางขนาด 128/256/384/512 จาก `docs/chunk_size_evidence.md` |
| 5 | การตัดสินใจหลัก 2: แนวทางการค้น | dense + BM25 ตัวอักษร 3 ตัว (convex α 0.6) และ rerank เป็นตัวเลือก; เหตุผลภาษาไทยไม่มีช่องว่างคำ; benchmark สาธารณะ 14 ชุด (hybrid ชนะ 6, แพ้ 4: บอกตรงๆ) |

| 8 | ผลการประเมินอย่างน้อย 2 metric | correctness (judge อ้างเฉลย) + Faithfulness แบบ RAGAS ที่เขียนเอง + BERTScore (เท่ากันทุกระบบ: บอกว่าเป็นสมบัติเมตริก) + citation/abstention; judge สองตัว (luna, Gemini) ตรงกัน 0.85–0.96; ข้อจำกัด: test 52 ข้อ ไม่มีคนตรวจ judge |
| 9 | Failure analysis: อะไรพังและทำไม | ค้นเก่งแต่ตอบไม่ผ่าน 9/52: ค้นพลาด 3, ตอบไม่ครบ 2, validator ตัดคำตอบถูก 2, อ้างชิ้นผิด 1, claim ขัดกัน 1; ตัวอย่างสด: ถาม metformin ระยะ 3, ข้อ q157 (ประชากรไม่ตรง) ในเดโม; ความปลอดภัย OWASP: 0.58 → 0/45; ชุดแก้ 2 ชุดไม่ผ่านกติกา |

## แผนเดโมสด (10 นาที) ใช้ปุ่มคำถามตัวอย่างใน `demo.py --web`
1. คำถามปกติ (HbA1c) → คำตอบ + แหล่งอ้างอิง + แผงหลักฐาน
2. metformin ระยะ 3 → คำตอบตามเกณฑ์ eGFR (ชี้ว่าเลข 3 จากคำถามเคยถูก validator ตัดและแก้แล้ว)
3. "ผู้ป่วยระยะนี้ใช้ยาเท่าไหร่" → งดตอบ; "ผมเป็นเบาหวาน กินยากี่เม็ด" → ปฏิเสธ; เจ็บหน้าอก → 1669
4. ข้อมูลส่วนบุคคล → ถูกปิดบังก่อนส่งให้โมเดล; injection → ถูกปฏิเสธ
5. จุดอ่อนที่ทราบ (q157) → ระบบตอบด้วยเกณฑ์ผู้ป่วยไตทั่วไป: ใช้เป็นตัวอย่างหัวข้อ failure analysis
(ก่อนขึ้นแสดง: `demo.py --check` และ `demo.py --warm` บนเครื่องที่จะใช้; คำถามตัวอย่างรันจากแคชได้แม้ไม่มีเน็ต)

## เตรียมตอบคำถาม (ต้องตอบเองโดยไม่ใช้ AI)
- ทำไมเลือก chunk ขนาดนี้ ถ้าเป็น 2 เท่าหรือครึ่งหนึ่งจะเกิดอะไร (`docs/chunk_size_evidence.md`)
- ถ้าตัดขั้นที่สอง (BM25 หรือ reranker) ออก คุณภาพเปลี่ยนอย่างไรและเพราะอะไร (README 5ก, `docs/hybrid_retrieval_experiment.md`)
- ผลไหนที่เซอร์ไพรส์ที่สุดและกลไกคืออะไร (ตัวเลือก: ReAct ไม่ชนะทั้งที่ค้นเองได้; BERTScore เท่ากันทั้งที่ correctness ต่างกัน; faithfulness ต่ำเกินจริงเพราะ claim ฝากบริบทไว้กับคำถาม)
- ทำไม ReAct แย่กว่า → query drift, ไม่มีเกณฑ์หยุด, บริบทเจือจาง (`docs/error_analysis_track_c.md`)
- เชื่อ judge ได้แค่ไหน → สอง judge ตรงกัน แต่ไม่มีคนตรวจและแปรปรวน ±0.03
- guard ปลอดภัยจริงไหม → วัดบนเคสที่ AI เขียน; 0/45 ไม่ใช่การรับรอง (ขอบบน CI ~8%)
