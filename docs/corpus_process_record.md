# บันทึกกระบวนการเตรียม corpus: ใครทำอะไร (คน, Claude, Codex, Typhoon)

สถานะ 2026-10-08 · corpus ล่าสุด `normalized-v7` · เจ้าของบันทึก: Track B (Up2mEz)

เอกสารนี้มีไว้อธิบายอาจารย์และเป็นต้นทางของ `AI_AUDIT.md` ทุกตัวเลขอ้างไฟล์หลักฐานได้ (ตารางท้ายเอกสาร)
อ้างอิงสไลด์รายวิชาเขียนเป็น `L14 p10` = NLP-DL-14 หน้า 10 (`inclass-souce/`)

## 1. สรุปสั้น (ไว้พูดตอนนำเสนอ)

เราเอา PDF แนวทางเวชปฏิบัติและสื่อความรู้ภาษาไทย 68 เอกสาร (4,009 หน้า) มาทำเป็นข้อความรายหน้าที่ค้นได้
หน้าที่ดึงข้อความจาก PDF ไม่ได้ (เป็นภาพ/ฟอนต์เสีย) ส่งเฉพาะ**ภาพหน้านั้น**ให้ Typhoon OCR อ่าน
จากนั้นตรวจความถูกต้องเป็นชั้น: เกณฑ์อัตโนมัติ → AI เทียบภาพ (Claude, Codex) → **คนตัดสินทุกหน้าที่ AI เสนอแก้**
AI ไม่เคยแก้ corpus เอง ทุกการแก้เป็น "ข้อเสนอ" ที่สคริปต์จะใช้ก็ต่อเมื่อคนติ๊กยอมรับ และทุกรุ่นของ corpus แยกโฟลเดอร์ ไม่เขียนทับ

```
PDF ─► ดึงข้อความ + วัดคุณภาพรายหน้า ─► หน้าติดธง ─► Typhoon OCR (ส่งภาพ PNG)
                                                     │
                     เกณฑ์อัตโนมัติ / Claude เทียบภาพ ◄┘
                                │
          Codex รอบ 1: ตรวจสุ่ม ─► พบว่าเกณฑ์อัตโนมัติไม่พอ ─► Codex รอบ 2: เสนอแก้ทีละจุด
                                                                  │
                    Claude ตรวจรูปแบบข้อเสนอ + สร้างหน้า review ◄──┘
                                │
                  คน (Up2mEz) ตัดสินทุกหน้า/ทุกจุด ─► สคริปต์ใช้เฉพาะที่ติ๊ก ─► normalized-v7 ─► ตรวจซ้ำอัตโนมัติ
```

## 4. ขั้นตอนตามลำดับ

### 4.1 หาเอกสารและทำ manifest (Track A + agent research, 5–6 ต.ค.)
- ทำ: ค้นแหล่งไทย (สมาคมวิชาชีพ, กรมควบคุมโรค, โรงเรียนแพทย์) → `data/manifests/documents.jsonl` (79 records) + rights queue
- เหตุผล: corpus ต้องเป็นของจริง ≥ 50 เอกสาร; กรองตั้งแต่ต้นทางว่าเป็นเอกสารไทย/ตรงขอบเขตโรค = ด่านแรกของ **data funnel** (`L14 p6`)
- หลักฐาน: `data/agent_runs/20261005-*`, `docs/corpus_policy.md`

### 4.2 ดาวน์โหลด + hash (Claude เขียนสคริปต์, คนดาวน์โหลดส่วนที่ถูกบล็อก)
- ทำ: `fetch_documents.py` เก็บ PDF + ใบเสร็จ (URL, เวลา, ขนาด, SHA-256); เว็บที่ตอบ 403 **ไม่ปลอม user-agent** ให้คนกดโหลดจากเบราว์เซอร์แล้ว `import_manual_downloads.py` ตรวจและ hash
- เหตุผล: SHA-256 ใช้ระบุไฟล์และกันซ้ำแบบ exact (`L14 p21`); การไม่หลบการบล็อกคือ **consent** และ least privilege ของ agent (`L13 p47`, `L13 p50`)

### 4.3 ดึงข้อความ + วัดคุณภาพรายหน้า (normalized-v2, 39 เอกสาร)
- ทำ: `extract_pages.py` / `normalize_thai.py` ดึงข้อความ, ซ่อมสระ/วรรณยุกต์ไทยลอย, ตัดหัว/ท้ายกระดาษซ้ำ, นับสถิติรายหน้า (อักษรไทย, สระลอย, อักขระเสีย) → `status` = ok / ok_minor_issues / degraded / garbled / empty
- เหตุผล: เป็น **heuristic filter ชั้นที่ 1** แบบ Gopher/C4 (`L14 p10–12`): กฎตายตัว ราคาถูก ตรวจซ้ำได้; และ "Load → Parse" ของ document pipeline (`L12 p6`): ขยะเข้า = ขยะถูกค้น

### 4.4 OCR หน้าที่ติดธง (Typhoon, v3/v5/v6)
- ทำ: `ocr_typhoon.py` ส่งเฉพาะหน้า empty-ที่มีภาพ / garbled / degraded: 90 + 10 + 334 = **434 หน้า**; ใช้ key ของสมาชิก 2 คนแบ่ง shard, จำกัด 18 req/min/key, retry 429, key อ่านจาก `.env` ไม่ถูกพิมพ์
- ผลเข้า corpus ด้วยสถานะ `ocr_unreviewed` ห้ามเข้า index จนกว่าจะผ่านการตรวจ
- เหตุผล: หลักฐานบางส่วนอยู่ในภาพ (`L12 p30` The Multimodal Challenge); แต่ OCR อาจได้ตัวอักษรแต่เสียโครงสร้างหรือแต่งข้อความ จึงต้องมีด่านตรวจ

### 4.5 ตรวจผล OCR ช่วงแรก (Claude, 7 ต.ค.)
- Claude เทียบภาพหน้ากับข้อความ 77 + 10 หน้า (`ai_assisted_visual_check`)
- อีก 330 หน้าใช้เกณฑ์อัตโนมัติ (อัตราคำในพจนานุกรม, ตัวเลข, รูปแบบข้อความแต่ง, การซ้ำ) → 276 หน้า `pass_auto` (`ai_assisted_risk_based`)
- หลักฐาน: `data/manifests/ocr_review_20261007{,b,c}.json` (ระบุผู้ตรวจว่าเป็น AI และ `human_confirmation: null`)

### 4.6 Codex รอบ 1 — ตรวจ (161 หน้า, read-only)
- Claude เลือก 115 หน้าที่มีปัญหา + สุ่ม 46 หน้าจาก `pass_auto`, เขียนคำสั่ง `TASK.md`
- Codex render ภาพหน้า (80 dpi; ใน sandbox ใช้ PDFium แทน pdftoppm), เปิดดูภาพ, เทียบกับข้อความ, ให้ verdict หนึ่งค่าต่อหน้า (`text_ok`, `text_wrong_numbers`, `text_invented`, ...)
- **ผลสำคัญ:** หน้า `pass_auto` ที่สุ่ม ถูกครบแค่ครึ่ง และ ~11% มีตัวเลข/เครื่องหมายผิด เช่น "> 126" แทน "≥ 126"
- การตัดสินใจ (คน): เกณฑ์อัตโนมัติไม่พอสำหรับข้อมูลทางคลินิก → ตรวจทุกหน้า pass_auto ด้วยภาพ + คน
- เหตุผลทางวิชา: นี่คือการประเมินตัวกรองด้วยตัวอย่าง: ทุก filter เป็น precision–recall trade-off (`L14 p6`); เป็นรายการ Error Catch Log ที่ดีใน AI Audit

### 4.7 Codex รอบ 2 — เสนอแก้ทีละจุด (283 หน้า)
- Claude เตรียมภาพ 110 dpi ล่วงหน้า และเขียน `TASK2.md` บังคับรูปแบบ: ข้อเสนอแต่ละจุดเป็น `{"old","new","kind","confidence","evidence"}`,
  `old` ต้องเป็นข้อความที่มีอยู่จริงและเจอ**ครั้งเดียว**ในหน้า (Codex ต้องตรวจด้วย Python), ห้ามเดาตัวเลข, ห้าม "ปรับสำนวน"
- Codex ได้ 280 จุดแก้: คำ 226, ชื่อยา 29, ตัวเลข 16, ลบข้อความแต่ง 7, เครื่องหมาย 1, หน่วย 1
- Claude ตรวจซ้ำ (`round2_validate.py`): ครบ 283 หน้า, ทุก `old` เจอครั้งเดียว
- เหตุผล: Constrained output + validate (`L13 p46` ชั้น 1–2); การบังคับให้อ้างข้อความตรงช่วยกัน hallucination ของ worker

### 4.8 คนตัดสิน (Up2mEz) → normalized-v7
- Claude สร้าง `review.html` (ภาพต้นฉบับคู่ข้อความ, ไฮไลต์จุดแก้, ติ๊กรายจุด, ตัดสินรายหน้า, export JSON; ทำงานในเครื่อง ไม่อัปโหลด)
- คุณตัดสิน: ใช้ 255 หน้า / ไม่ใช้ 28, รับ 237/240 จุด, โน้ต p89 (สะกด "อัลฟ่ากลูโคซิเดซอินฮิบิเตอร์"), p115 คงเดิม
- `apply_review_decisions.py` ใช้เฉพาะจุดที่ติ๊ก หาตำแหน่งจากข้อความเดิม ถ้าชนกันแบบกำกวมให้ล้ม (ไม่เดา); บันทึก `reviewed_by`, `proposed_by`, `review_method: human_verified_ai_proposed`
- ตรวจรุ่นใหม่: schema 0 error, 67 เอกสาร/3,873 หน้าเข้า index, ไม่มีหน้า pass_auto ค้าง, ไม่มีข้อความแต่งค้าง
- เหตุผล: human-in-the-loop สำหรับงานความเสี่ยงสูง (`L13 p46` Escalate, `L13 p47` "pause for human confirmation and keep an audit log", `L11 p21` least privilege + confirm risky actions with a human)

### 4.9 ป้ายประชากรและข้อมูลส่วนบุคคล → normalized-v8 (กำลังตัดสิน)
- รอบแรกใช้ regex (มีคำว่าเด็ก/ตั้งครรภ์/ชื่อมีคำนำหน้า) แล้วพบว่าผิดมาก: ผู้ตรวจชี้ว่า**ต้องดูบริบทของหน้า** เช่น ชื่อผู้จัดทำแผ่นพับไม่ควรลบ เบอร์หน่วยงานเก็บได้ รายชื่อทั้งหน้าต้องแยกให้ตัดสิน
- ตอนนี้ `page_context.py` ตัดสินจากหลักฐานหลายอย่างของหน้าและของบท (ดู [page_context_evaluation.md](page_context_evaluation.md)): ป้ายประชากรวัดเทียบสารบัญ DM CPG ได้ precision 1.00 / 0.80 (เด็ก / ตั้งครรภ์) จาก 0.50 / 0.14; หน้าที่ต้องตัดสินเรื่อง PDPA ลดจาก 340 เหลือ 142; ข้อมูลติดต่อแยกเป็นหน่วยงาน (เก็บ) / บุคคล (เสนอลบ) / กำกวม (ดูเอง)
- ผู้ตรวจตัดสินในหน้า review (แท็บ 0 เป็นกลุ่มพร้อมภาพตัวอย่าง) แล้ว `apply_page_tags.py` สร้าง v8: ป้าย `population` ทุกหน้า, ลบค่าที่เลือกทุกฟิลด์ข้อความ, `index_exclusion` สำหรับหน้าที่ตัด, `pdpa_tag: personal_name_list` สำหรับหน้ารายชื่อที่เก็บแต่ไม่ให้ค้น, `needs_ocr` สำหรับข้อความเสียที่ส่ง OCR ใหม่
- เหตุผล: FineWeb ใส่ **PII removal** เป็นด่านหนึ่งของ pipeline (`L14 p10`) และ Dolma มี PII tagger (`L14 p18`); ข้อมูลซ้ำเพิ่มความเสี่ยง memorisation/privacy (`L14 p20`); PDPA หลัก data minimisation: เก็บเฉพาะที่จำเป็นต่อวัตถุประสงค์ (ตอบคำถามทางคลินิก) · ทุกการตัดสินใจเป็นของคน ระบบแค่เสนอพร้อมเหตุผล (`L13 p46–47`)

### 4.10 หน้าเนื้อหาน้อยและข้อความเสีย (ก่อน chunk)
- ที่มา: ผู้ตรวจกังวลว่าปก/หน้าหัวข้อ/ท้ายเล่ม (คำคม) ที่ข้อความน้อยจะทำให้ chunk ไม่ดีและ retrieval แย่
- วัดปริมาณเนื้อหาด้วย "จำนวนตัวอักษรไทย/อังกฤษ/ตัวเลข" ของหน้า (ไม่นับช่องว่าง เครื่องหมาย และคำนำทาง) ใน 3,873 หน้าที่เข้า index: น้อยกว่า 100 ตัวอักษร 172 หน้า (4%), น้อยกว่า 150 ตัวอักษร 259 หน้า (7%)
- ตัวตรวจใน `build_page_tag_review.py` มี 8 ชนิด: ข้อความเสียจากรหัสฟอนต์, ปุ่มนำทางอย่างเดียว, แทบไม่มีข้อความ, หน้าคั่นบท, ปก (3 หน้าแรก), ปกหลัง (3 หน้าสุดท้าย), คำบรรยายรูป/ตาราง, ข้อความน้อยกลางเล่ม; แต่ละชนิดมีค่าแนะนำ (ตัด/เก็บ) คนตัดสินรายหน้าในแท็บ 3
- **ไม่ตัดอัตโนมัติ** เพราะหน้าสั้นกลางเล่มบางหน้าเป็นตารางเกณฑ์หรือแผนภาพที่สำคัญ (เช่น คำบรรยายรูปแนวทางการฟอกไต) ตัดเฉพาะที่คนยืนยัน และข้อความเดิมยังอยู่ในไฟล์เพื่อตรวจย้อนได้

## 8. คำถามที่อาจารย์อาจถาม

- **ทำไมไม่ OCR ทุกหน้า?** หน้าส่วนใหญ่ (3,262) ดึงข้อความจาก PDF ได้ถูกต้องอยู่แล้ว การ OCR ซ้ำเพิ่มโอกาสผิดและส่งข้อมูลออกนอกเครื่องโดยไม่จำเป็น จึง OCR เฉพาะหน้าที่เกณฑ์ชั้น 1 ติดธง (`L14 p10` cheap-first)
- **ทำไมไม่ให้ AI แก้อัตโนมัติ?** รอบ 1 พบว่าแม้ผ่านเกณฑ์อัตโนมัติก็ยังผิดเรื่องตัวเลข/เครื่องหมาย ~11% ซึ่งในแนวทางเวชปฏิบัติอาจทำให้ตอบผิดทางคลินิก จึงให้ AI แค่เสนอ และคนเป็นผู้ตัดสิน
- **รู้ได้อย่างไรว่า AI ไม่แต่งข้อความ?** (1) ตัด `<figure>` ที่ Typhoon บรรยายภาพเอง (2) Codex ต้องอ้าง `old` ที่มีจริงครั้งเดียว (3) Claude ตรวจทุกข้อเสนอด้วยสคริปต์ (4) คนดูภาพต้นฉบับคู่ทุกหน้า (5) สคริปต์ตรวจรุ่นใหม่หาข้อความแต่งค้าง = 0
- **ยังเหลือความเสี่ยงอะไร?** 99 หน้า OCR ที่ AI ตรวจอย่างเดียว; หน้า PDF ปกติไม่ได้เทียบภาพทุกหน้า; แผนภาพ ~17 หน้าไม่ได้ถอดเป็นข้อความ (ตัดสินไม่ทำ visual RAG, ดู security_and_ethics.md)
- **PDPA?** corpus ไม่มีข้อมูลผู้ป่วย; ชื่อและข้อมูลติดต่อของผู้จัดทำจัดการในขั้น 4.9; demo จะไม่บันทึกคำถามผู้ใช้
