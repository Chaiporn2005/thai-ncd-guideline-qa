# ข้อค้นพบ: คำถามกับเอกสารใช้หน่วยหรือคำเรียกต่างกัน (พบ 2026-10-10 ตอนตรวจ gold q126)

## เจออะไร

q126 ถาม "น้ำตาลต่ำกว่าเท่าไรจึงเข้าข่ายน้ำตาลตก" หลักฐานคือแผ่นพับ Siriraj `dm-siriraj-hypoglycemia-leaflet-undated` หน้า 1 เขียนว่า
"ต่ำกว่า 70 มิลลิกรัม/เดซิลิตร" ไม่มี mmol/L ในหน้านั้น (นับ `mmol`/`มิลลิโมล` ได้ 0)
ถ้าผู้ใช้ถามเป็น mmol/L (3.9 mmol/L) retrieval ปัจจุบัน (dense + BM25 + RRF) ไม่มีขั้นแปลงหน่วย BM25 จับคำตรง ๆ จึงไม่เชื่อมสองหน่วย
เอกสารเล่มอื่น (เช่น `dm-remission-implementation-lessons-undated`) มี "70 มก/ดล (3.9 mmol/L)" ถ้าค้นได้เล่มนั้น คำตอบถูก แต่ Recall@k ตาม gold ของ q126 นับว่าพลาด

เป็นกรณีเดียวกับปัญหาทั่วไป: หน่วยต่างกัน, คำย่อ (มก/ดล / มิลลิกรัม/เดซิลิตร / mg/dL), ชื่อยาไทย-อังกฤษ, ชื่อโรคคนละคำ

## ตัวเลือก

1. พจนานุกรมหน่วยใน `query_rewrite.py`: ทำเร็ว แต่ต้องไล่เคสเอง ไม่ครอบคลุม
2. normalize หน่วยในเอกสาร/คำค้น (`normalize_thai.py`): ช่วย BM25 แต่ต้องไล่เคสเอง
3. LLM ในขั้น generator (และ/หรือ query rewrite ด้วย LLM): ครอบคลุมเคสที่คาดไม่ถึงได้ดีกว่า

## แนวทางที่เลือก (ผู้ใช้ตัดสิน 2026-10-10)

ไม่ทำกฎเฉพาะหน่วยใน retrieval ให้ LLM จัดการ
ข้อควรระวัง:
- generator แก้ได้เฉพาะเมื่อ retrieval ดึงหน้าที่เกี่ยวข้องมาแล้ว (top-k) ถ้าหน้าเฉลยไม่ถูกดึง generator ไม่มีข้อมูลให้ตอบ
  จึงควรให้ LLM ช่วยที่ขั้น query rewrite ด้วย (มี `query_rewrite.py` และ LLM client อยู่แล้ว) ไม่ใช่เฉพาะตอนตอบ
- หน่วยที่แปลงเอง (หาร 18 ฯลฯ) ต้องบอกในคำตอบว่าเป็นค่าที่คำนวณ ไม่ได้อ้างจากเอกสาร และตรวจกับ gold ก่อนใช้ (ความเสี่ยงทางคลินิก)
- ใน gold ถือหน่วยตามเอกสารต้นทาง ไม่แก้ gold เพื่อรองรับหน่วยอื่น
