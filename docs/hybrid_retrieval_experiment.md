# การทดลอง hybrid retrieval และเทคนิคเพิ่มความแม่น: ทำอะไร เพราะผลอะไร ค่ามาจากไหน

บันทึกต่อเนื่องของ Track B (2026-10-10). **คำถามทั้งหมดยังเป็น silver (AI ร่าง ยังไม่มีคนตรวจ)** ตัวเลขจึงเป็น pilot บน dev 100 ข้อที่ตอบได้ ห้ามรายงานเป็นผล
ต้องยืนยันซ้ำบน gold ก่อน และ test ยังไม่ถูกแตะ. ทุกค่าพารามิเตอร์มีที่มาในไฟล์ `configs/retrieval/hybrid_sweep_v1.json` (ฟิลด์ `source`) ค่าที่ไม่มีงานวิจัยรองรับระบุว่าเป็น "ของเราเอง"
กติกาเลือกค่าเขียนไว้ก่อนรัน: แต่ละขั้นเลือกค่าที่ Recall@5 สูงสุด ถ้าช่วงเชื่อมั่น (95% bootstrap แบบคู่) ของผลต่างกับค่าอ้างอิงคร่อมศูนย์ให้ติดป้าย "แยกไม่ออก" และถือเป็นค่าชั่วคราว

## 0.1 ยืนยันบน gold dev (80 ข้อ ผ่านการตรวจโดยคน ไม่มีข้อ silver) 2026-10-11

รัน sweep ชุดเดิม (กติกาเลือกค่าเดิม) บนคำถาม dev ที่เป็น gold เท่านั้น (`hybrid-gold-{bge-m3,e5-base}`). **convex combination ยังชนะ dense ล้วน** และผลต่างยังมีนัยสำคัญ:
- bge-m3: dense R@5 0.806 (R@1 0.406, MRR@10 0.580); CC α=0.6 ต่าง +0.069 (CI +0.006…+0.138), α=0.7 +0.050 (CI 0.000…+0.113); ค่า α ที่ดีสุดขยับจาก 0.7 เป็น 0.6 จึงควรใช้ช่วง α 0.5–0.7 ไม่ใช่ค่าเดียว
- e5-base: dense R@5 0.744 (R@1 0.338, MRR@10 0.518); CC α=0.5 ต่าง +0.106 (CI +0.037…+0.194, ชนะ 10 แพ้ 1)
- ตัวตัดคำ/พารามิเตอร์ BM25/RRF k ยังแยกไม่ออก และค่าที่ถูกเลือกเปลี่ยนไปตามชุดคำถาม (bge-m3: char3, anserini_tuned_for_expansion, RRF k10; e5: newmm_latin, lucene_default, RRF k30) ซึ่งตอกย้ำว่าเป็นการเลือกจากสัญญาณรบกวน ไม่ควรเสียเวลาจูนเพิ่ม

## 1. ฐานที่ใช้เทียบ

dense ด้านเดียวแบบ parent-child (child 128 → parent 512) ซึ่งเป็นตัวที่ดีที่สุดจาก pilot รอบก่อน; ด้าน lexical ทำที่ระดับ parent 512 (4,386 หน่วย). bge-m3: R@5 0.795; e5-base: R@5 0.725

## 4. ถ่วงน้ำหนักกลุ่มโรค/ประชากร (soft boost): ผลเชิงลบ

ทดสอบบนฐาน hybrid ที่ดีที่สุดของ bge-m3 (`scripts/experiment_boost.py`; ค่า tau, w เป็นของเราเอง ไม่มีงานวิจัยกำหนด):
- ถ่วงกลุ่มโรค: ไม่ดีขึ้นที่ w ≤ 0.2 (ต่าง 0.000) และแย่ลงเล็กน้อยที่ w สูง (−0.01…−0.03); ตัวทายกลุ่มจากเซนทรอยด์ของ embedding แม่นเพียง 66%
- ถ่วงประชากร (เด็ก/ตั้งครรภ์/สูงอายุ): มีคำถามที่ระบุกลุ่มเพียง 9 ข้อ ผลต่าง 0 ทุกค่า
- **สาเหตุ** (`scripts/analyze_misses.py`): ที่พลาด R@5 14 ข้อ มี 13 ข้อที่กลุ่มโรคที่ถูกอยู่ใน top-5 แล้ว และ 11 ข้อมีกลุ่มนั้นเป็นส่วนใหญ่ ความสับสนอยู่ **ภายในกลุ่มโรคเดียวกัน** (คนละเอกสารหรือคนละหน้า) ไม่ใช่ข้ามกลุ่ม. ในจำนวนนั้นเอกสารที่ถูกอยู่ใน top-5 แต่ผิดหน้า 6 ข้อ, อยู่อันดับ 6–30 อีก 4 ข้อ, ไม่อยู่ใน top-30 อีก 4 ข้อ
- ข้อสรุป: ไม่ควรลงแรงกับ boost ตามกลุ่มโรคต่อ; ช่องที่เหลือคือการจัดอันดับใหม่ในกลุ่มเดียวกัน (reranker) และการเชื่อมคำถามภาษาพูดกับถ้อยคำทางการ (doc2query)

## 5. Reranker (ข้อ 2): ช่วยอันดับต้น แต่ช้ามากบน CPU

| hybrid | 0.475 | 0.855 | 0.875 | 0.632 | – |
| rerank top-10 | 0.535 | 0.850 | 0.875 | 0.684 | +0.053 (−0.008…+0.117) |

- ข้อสรุปชั่วคราว: เหมาะเป็นตัวเลือก "โหมดแม่นยำ" ที่รันบน GPU ถ้ามี ไม่ใช่ค่าเริ่มต้นบน CPU

| ทั้งสองฝั่ง | 0.790 / 0.646 (−0.065, CI −0.145…+0.02) | 0.785 / 0.643 (−0.045, CI −0.125…+0.03) |
| dense + คำถามล้วน (ไม่มี BM25) | 0.725 / 0.554 (−0.130, CI −0.215…−0.04) | 0.585 / 0.439 (−0.245, CI −0.345…−0.14) |

- ทั้งสองโมเดลทิศทางเดียวกัน: **BM25 + คำถามช่วยเล็กน้อยโดยเฉพาะอันดับแรก** (R@1 0.475 → 0.525 และ 0.445 → 0.505) แต่แยกจากสัญญาณรบกวนไม่ออก; **คำถามใน dense ไม่ช่วยและทำให้แย่ลงเมื่อไม่มี BM25**
- สาเหตุที่น่าจะเป็น: คำถามที่ Codex สร้างจากเอกสารอื่นหน้าตาคล้ายคำถามผู้ใช้พอๆ กับของเอกสารที่ถูก (คำถาม dev ที่คำถามที่สร้างไว้ใกล้ที่สุดมาจากเอกสารที่ถูกเพียง 60 จาก 100 ข้อ ใน bge-m3 และ 55 จาก 100 ใน e5) จึงดึงเอกสารผิดขึ้นมา
- ค่า BM25 "tuned2" (k1 2.18, b 0.86) เท่ากับค่าที่ sweep เลือกไว้อยู่แล้ว (ได้ผลเหมือนกัน) จึงยังไม่ได้เทียบกับค่าอื่นหลังขยาย
- **ข้อควรระวัง:** คำถาม gold และคำถาม doc2query มาจาก LLM ตระกูลเดียวกันและหน้าเดียวกัน ผลจึงมีโอกาสดีเกินจริง (ซึ่งยังไม่ช่วย dense เลย); ต้นทุนสูง (2.6 ล้าน tokens ต่อ 4,386 chunk)
