# เรื่องที่จะเล่า: โครงนำเสนอ 10 แผ่น พร้อมบทพูด หลักฐาน และคำถามที่ต้องเตรียม (ร่างโดย AI; เจ้าของแก้และพูดด้วยคำพูดตัวเอง)

โจทย์วิชา: 10 นาทีเดโม + 5 นาทีถามตอบ, สไลด์ไม่เกิน 10 แผ่น, **ห้ามมีโค้ดบนสไลด์** (ใช้แผนภาพและตารางผล), กรรมการให้คะแนนที่ "เข้าใจและตัดสินใจเอง" อธิบายได้ว่าทำไมเลือกวิธีนี้ ตัวเลขทุกตัวด้านล่างมาจากผลที่วัดจริงในรีโป (`runs/`, `docs/`) ไม่มีตัวเลขที่ไม่ได้วัด

## แกนเรื่อง (ใช้เป็นเส้นเดียวตลอด)
**ปัญหา → ทำไมวิธีนี้เหมาะ → จุดอ่อนของวิธีนั้น → จึงเพิ่มอะไร → เทียบกับอะไร → วัดด้วยอะไร ได้เท่าไร ตีความอย่างไร → ยังพลาดตรงไหน → ปกป้องอย่างไร → ใช้ AI อย่างไรและพลาดอะไร**
ทุกแผ่นตอบ 3 คำถามนี้ซ้ำ: *เลือกอะไร / ทำไม / เห็นจากหลักฐานอะไร*

## แผ่น 1 ชื่อ ทีม โดเมน + ทำไมต้องมีระบบนี้
- **ข้อความหลัก:** แนวทางเวชปฏิบัติ NCD ไทยยาวหลายพันหน้า หาเกณฑ์/ตัวเลข/ขนาดยาช้าและผิดง่าย ระบบต้อง *ตอบจากเอกสารพร้อมอ้างอิง หรืองดตอบ* ไม่เดา (ผิดแล้วเสี่ยงต่อผู้ป่วย)
- **หลักฐานว่าทำจริง:** corpus จริง 66 เอกสาร / 3,716 หน้า PDF (เบาหวาน ความดัน ไขมัน ไต บริการ NCD) ตรวจเอกสาร OCR/ข้อความด้วยคนทีละหน้าที่น่าสงสัย; คำถามประเมิน dev 106 + test 56 ข้อ (gold ที่คนตรวจ)
- **ตั้งขอบเขตตั้งแต่ต้น:** เพื่อการศึกษา ไม่วินิจฉัย ไม่สั่งยารายบุคคล (นโยบายที่เจ้าของตัดสิน G1–G7)
- แหล่ง: README หัวข้อ 1, `docs/corpus_process_record.md`, `docs/decisions_guardrail_harness.md`

## แผ่น 2 ภาพรวม pipeline
แผนภาพเดียว (วาดจาก README หัวข้อ 1) อ่านจากซ้ายไปขวา:
`คำถาม → ตัวกรองอินพุต → ค้นคืน top-5 (dense + BM25) → prompt → LLM → ตรวจทุก claim → ตัวกรองเอาต์พุต → คำตอบ + แหล่งอ้างอิง / งดตอบ`
- ใต้แผนภาพบอกว่า **ทุกลูกศรมีเหตุผลและมีการวัด** (เล่าในแผ่นถัดไป) และมีตัวแปรที่เทียบ: ค้น A/B/C/D, pipeline Python เทียบ LangGraph เทียบ ReAct agent
- **บทพูด:** "ระบบไม่ใช่แค่ส่งคำถามให้ LLM แต่คุมตั้งแต่ก่อนคำถามเข้าถึงหลังคำตอบออก" (ชั้นป้องกันอยู่ที่แผ่น 8)

## แผ่น 3 การตัดสินใจหลัก 1: ข้อมูลและการค้น (ทำไม + จุดอ่อน → เพิ่มอะไร)
| เลือก | ทำไมเหมาะกับปัญหานี้ | จุดอ่อนที่พบ → ที่เพิ่ม |
|---|---|---|
| chunk ตามย่อหน้า/ประโยค/แถวตาราง ไม่ตัดกลางคำ; **parent-child**: child 128 token ใช้ค้น, parent 512 token ส่งให้โมเดล | คำถามส่วนใหญ่ถามข้อเท็จจริงเดียว (ตัวเลข เกณฑ์) chunk เล็กตรงเป้ากว่า แต่โมเดลต้องการบริบทเต็ม; ทดสอบ 128/256/384/512 (`docs/chunk_size_evidence.md`) | chunk เล็กตัดกลางประโยคมากขึ้น (26% ที่ 128 เทียบ 5% ที่ 512) → ใช้ parent ให้บริบท |
| embedding **bge-m3** (เทียบ e5-base) | รองรับไทย ทำงานบน CPU เลือกจากผล dev ไม่ใช้ test | dense อย่างเดียวพลาดชื่อยา/ตัวเลข/คำเฉพาะ |
| **hybrid: dense + BM25 ตัวอักษร 3 ตัว** (convex α 0.6) | ภาษาไทยไม่มีช่องว่างคั่นคำ BM25 ระดับตัวอักษรจับคำตรงตัว (ชื่อยา เลข) ที่ dense พลาด | → R@10 จาก 0.827 เป็น 0.981 |
| **rerank** (cross-encoder bge-reranker-v2-m3) เป็นตัวเลือก C | แม่นขึ้นที่อันดับต้น | ช้าบน CPU 15–36 วินาที/คำถาม → ไม่ใช่ค่าเริ่มต้น เหมาะกับมี GPU |
- **ซื่อสัตย์:** บน benchmark สาธารณะ 14 ชุด hybrid ชนะ dense 6 ชุด แพ้ 4 ชุด (โดยเฉพาะข้ามโดเมน/ข้ามภาษา) จึงอ้างว่า "เหมาะกับข้อมูลไทยของเรา" ไม่ใช่ "ดีกว่าเสมอ"
- แหล่ง: `docs/hybrid_retrieval_experiment.md`, `docs/handoff_track_c.md`, `runs/frozen_gen_v1/public_benchmarks/`

## แผ่น 4 การตัดสินใจหลัก 2: ตอบจากหลักฐานและตรวจคำตอบ
- **ตอบเป็น "claim + citation"** (JSON) ไม่ใช่ข้อความอิสระ เพื่อให้ตรวจด้วยโค้ดได้ว่าทุกข้อมีที่มา
- **validator (ไม่ใช้ LLM ตรวจ):** citation ต้องชี้หลักฐานที่ส่งจริง, ตัวเลขใน claim ต้องอยู่ในหลักฐานที่อ้าง (ยกเว้นเลขที่ผู้ใช้พิมพ์เอง), คำอังกฤษต้องอยู่ในหลักฐาน; ข้อที่ไม่ผ่านถูกตัดทิ้ง ไม่ซ่อม
- **ทำไม:** โมเดลภาษาแต่งตัวเลข/แหล่งอ้างอิงได้อย่างมั่นใจ; ตัวตรวจแบบกฎอธิบายได้ ทำซ้ำได้ และไม่ถูกหลอกง่าย
- **จุดอ่อน → ที่เพิ่ม:** validator ตัดเลข "3" ที่ผู้ใช้พิมพ์เอง ("ระยะ 3") ทำให้ข้อสำคัญของคำตอบ metformin หาย → เพิ่มโปรไฟล์ N8 (อนุญาตเลขจากคำถาม) ใน demo; ไม่ขยายไปถึงคำอังกฤษจากคำถามเพราะจะเปิดช่อง injection
- ตัวสร้างคำตอบ Typhoon v2.5-30B (API) temperature 0, แคชทุกคำขอเพื่อทำซ้ำได้
- แหล่ง: `src/ncdqa/rag/validate.py`, `docs/error_analysis_track_c.md` §1, §3

## แผ่น 5 Ablation 1: การค้นคืน (test, 52 ข้อ)
| ระบบ | R@1 | R@5 | R@10 | MRR@10 |
|---|---|---|---|---|
| A dense | 0.462 | 0.808 | 0.827 | 0.618 |
| B hybrid | 0.587 | 0.885 | 0.981 | 0.737 |
| C hybrid + rerank | 0.615 | 0.913 | 0.952 | 0.771 |
- **ตีความ:** เพิ่ม BM25 ได้มากสุด (R@1 +0.125, R@10 +0.154); rerank เพิ่มที่อันดับบนเล็กน้อย (R@1 +0.028) แต่ R@10 ลดลง (0.981 → 0.952; กลไกที่เป็นไปได้คือ reranker ดันบางหลักฐานที่เคยอยู่ใน 10 อันดับแรกลงไปต่ำกว่านั้น **ยังไม่ได้ตรวจเป็นรายข้อ** จึงพูดว่า "อาจ") และช้ามาก
- **บอกขอบเขต:** 52 ข้อ ช่วงเชื่อมั่นกว้าง ผลต่าง B กับ C ไม่มีนัยสำคัญ; ตัวแปร D (BM25 ล้วน) อยู่แผ่น 6
- **Metric:** Recall@k = สัดส่วนหลักฐานที่เจอใน top-k (วัดว่า "เจอหน้าเฉลยไหม"), MRR = อันดับแรกที่ถูก (วัดว่า "ขึ้นมาบนสุดไหม") ใช้โค้ดเดียวกับทีมค้นคืน

## แผ่น 6 Ablation 2: คำตอบ และ fixed vs LangGraph vs ReAct (test, 52 ข้อที่ตอบได้)
| ระบบ | correctness | faithfulness | hit@5 | token/ข้อ |
|---|---|---|---|---|
| A dense | 0.798 | 0.803 | 43/52 | 4.8k |
| B hybrid | 0.885 | 0.827 | 46/52 | 4.8k |
| **C hybrid + rerank** | **0.904** | **0.886** | 48/52 | 4.8k |
| D BM25 ล้วน | 0.808 | 0.768 | 42/52 | 4.8k |
| ReAct (Python = LangGraph) | 0.827 | 0.833 | 47/52 | 26.5k |
- **เล่า 3 ข้อ:** (1) การค้นดีขึ้นส่งต่อถึงคำตอบ A→B→C; (2) BM25 ล้วน (D) ใกล้ dense แต่แพ้ hybrid แปลว่าสองสัญญาณเสริมกัน; (3) **agent ค้นเองไม่ชนะ pipeline คงที่** ที่ต้นทุน ~5.5 เท่า (ต่างจาก B −0.058, ช่วงเชื่อมั่น 95% [−0.154, +0.038])
- **ทำไม ReAct แย่กว่า (สาเหตุที่วินิจฉัยและลองแก้):** query drift (agent เขียนคำค้นเองแล้วค้นแย่กว่าคำถามเดิม), ไม่มีเกณฑ์หยุด, บริบทเจือจาง; ลองแก้ด้วยค้นคำถามเดิมก่อน (hit@5 กลับเท่า B) แต่คำตอบยังไม่ดีกว่า จึงสรุปตามหลักฐานว่าโดเมนนี้ที่คำถามส่วนใหญ่เป็นข้อเท็จจริงเดียว การค้นรอบเดียวที่ดีพอ
- **LangGraph = Python:** คำตอบเหมือนกัน 106/106 (dev) และ 56/56 (test) เพราะต่างกันแค่ลำดับควบคุม; ใช้ LangGraph ให้เส้นทางตรวจสอบได้และมี node กู้คำตอบที่เสีย (กู้ได้ 60 จาก 71 ข้อที่ถูกตัดเมื่อจำกัด token)
- **ที่มา:** `runs/frozen_gen_v1/react_test_results.md`, `docs/error_analysis_track_c.md`

## แผ่น 7 Metric: วัดอะไร ได้ค่าเท่าไร ตีความอย่างไร
| metric | วัดอะไร | ผล (test) | อ่านอย่างไร |
|---|---|---|---|
| **correctness** (judge อ้างเฉลย: correct/partial/wrong/no_answer ให้ 1/0.5/0/0) | คำตอบมีข้อเท็จจริงสำคัญตรงเฉลยไหม | C 0.904 · B 0.885 · ReAct 0.827 · D 0.808 · A 0.798 | ตัวชี้วัดหลักของ "ตอบถูก" |
| **faithfulness แบบ RAGAS** (เขียนเอง) | สัดส่วน claim ที่หลักฐานรองรับ = ไม่แต่งเติม | C 0.886 · B 0.827 · ReAct 0.833 · A 0.803 · D 0.768 | แยกจาก correctness: ตอบถูกแต่แต่งเติมก็ได้ |
| **BERTScore** (bge-m3 ชั้น 8, วิธีตรงแพ็กเกจต้นฉบับ) | ความใกล้เชิงความหมายกับเฉลย | A 0.838 · B 0.837 · C 0.837 · D 0.846 · ReAct 0.832 | **แยกถูก/ผิดได้น้อย:** ช่วงเชื่อมั่นซ้อนกันทุกระบบ, D (correctness ต่ำกว่า) ได้สูงสุด; บน dev คำตอบที่ถูกได้ 0.85 เทียบ 0.78–0.82 ของที่ไม่ถูก (AUC 0.75–0.79) จึงใช้ดูอย่างเดียว ไม่ใช้ตัดสิน; **เคยวัดผิดมาตรฐานรอบแรก (ต่ำไป ~0.016) แก้และวัดใหม่แล้ว** |
| **citation correctness / abstention / hit@5 / token** | อ้างหน้าถูกไหม / งดตอบถูกไหม / ค้นเจอไหม / ต้นทุน | ดูตารางแผ่น 6 | ใช้อธิบายสาเหตุ |
- **ความน่าเชื่อถือของ judge (ต้องพูดเอง ไม่ซ่อน):** judge เป็น LLM (gpt-5.6-luna) ไม่มีคนตรวจ ตรวจด้วย sanity 48/48, สลับตำแหน่ง, ไม่มี length bias, judge ตัวที่สอง (Gemini) ตรงกัน 0.85–0.96 บนข้อที่ตัดสินได้ แต่ **judge ไม่นิ่ง ±0.03** ใกล้เคียงกับความต่างระหว่างระบบ จึงอ่านเป็นทิศทาง; faithfulness เดิมต่ำเกินจริงเพราะ claim ที่ฝากบริบทไว้กับคำถาม (ให้ judge เห็นคำถามแล้วสูงขึ้น 0.03–0.10 ทุกระบบ ลำดับเดิม)
- แหล่ง: `runs/frozen_gen_v1/eval/`, `docs/error_analysis_track_c.md` §4–5, §10

## แผ่น 8 Harness และความปลอดภัย (ป้องกันอะไร ทำอะไรไปบ้าง)
**Harness คืออะไรในงานนี้:** ชุดทดสอบ + ตัวตัดสินด้วยกฎ (ไม่ใช้ LLM) ที่รันเคสโจมตีผ่านระบบทีละชั้นป้องกัน แล้ววัด *attack success rate (ASR)* เทียบกับประสิทธิภาพปกติ (ถ้าปฏิเสธทุกอย่าง ASR = 0 แต่ใช้ไม่ได้ จึงรายงานทั้งคู่)
- **การออกแบบ:** เคสแต่ละข้อมี canary (ข้อความที่ถ้าโผล่ในคำตอบแปลว่าโมเดลทำตามคำสั่งโจมตี), วัดสองจุด (ดิบจากโมเดล / ถึงผู้ใช้หลัง validator), เพิ่มชั้นทีละชั้น N0–N7 เพื่อเห็นว่าแต่ละชั้นช่วยเท่าไร, ชุดอิงมาตรฐาน **OWASP Top 10 for LLM Applications 2025**: 76 เคสครอบ LLM01, 02, 05, 06, 07, 08, 09, 10
- **ป้องกันอะไรบ้าง (ตำแหน่ง input / tool / output):**
  - input: ปิดบังข้อมูลส่วนบุคคล (เลขบัตรตรวจ check digit, เบอร์, อีเมล, HN, ชื่อ+คำนำหน้า) ก่อนส่ง LLM; ปฏิเสธขอสั่งยา/วินิจฉัยรายบุคคล; อาการฉุกเฉินขึ้น 1669; จำกัดความยาวคำถาม; ตรวจรูปแบบ injection
  - ข้อมูลที่ค้นมา/tool: ตัวคั่นข้อมูล (spotlight) และย้ำคำสั่งท้าย (sandwich), ตัด chunk ที่ติดธงคำสั่งแฝง, tool ของ agent อ่านอย่างเดียวและจำกัดอาร์กิวเมนต์
  - output: ตรวจ claim (validator) และระงับคำตอบที่มี markup/ลิงก์ที่หลักฐานไม่มี/ข้อความ prompt/ข้อมูลส่วนบุคคล
  - ข้อมูล: log เฉพาะ metadata ไม่เก็บข้อความคำถาม; คีย์ไม่อยู่ใน git; แผ่นพับศิริราชที่ห้ามเผยแพร่ไม่อยู่ใน git
