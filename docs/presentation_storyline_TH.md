## แกนเรื่อง
ปัญหา → ทำไมวิธีนี้เหมาะ → จุดอ่อนของมัน → จึงเพิ่มอะไร → เทียบกับอะไร → วัดด้วยอะไร ได้เท่าไร ตีความอย่างไร → ยังพลาดตรงไหน → ปกป้องอย่างไร → ใช้ AI อย่างไรและพลาดอะไร
ประโยคเปิดที่ควรใช้ซ้ำทุกแผ่น: *"เราเลือก ___ เพราะ ___ และเห็นจาก ___"*

## แผ่น 1 ชื่อ ทีม โดเมน + ทำไมต้องมีระบบนี้ (0:45)

**บทพูด:** "แนวทางเวชปฏิบัติไทยยาวหลายพันหน้า คนทำงานหาเกณฑ์หรือขนาดยาได้ช้าและผิดง่าย ถ้าระบบตอบผิดอย่างมั่นใจ ผู้ป่วยเสี่ยง เราจึงตั้งเป้าว่าระบบต้องตอบจากเอกสารพร้อมแหล่งอ้างอิง หรืองดตอบ ไม่เดา เราใช้เอกสารจริงที่ตรวจเองทีละหน้าที่น่าสงสัย และชุดคำถามที่คนตรวจ"
**หลักฐาน:** README หัวข้อ 1; `docs/corpus_process_record.md` (คนตัดสินทุกหน้า OCR 283 + 90 หน้า); `docs/decisions_guardrail_harness.md` (ขอบเขต G1–G7: เพื่อการศึกษา ไม่วินิจฉัย ไม่สั่งยารายบุคคล)
**ถ้าถูกถาม:** "ทำไมเลือกโดเมนนี้" → ข้อมูลจริงมีโครงสร้างตัวเลข/ตาราง/เงื่อนไข ทำให้เห็นความต่างของวิธีค้นและตัวตรวจได้ชัด; ความเสี่ยงสูงจึงต้องมีการปฏิเสธ

## แผ่น 2 ภาพรวม pipeline (1:00 + เดโม 1 ข้อ)
**บนสไลด์:** แผนภาพเดียว อ่านซ้ายไปขวา (ใช้แผนภาพใน README หัวข้อ 1):
`คำถาม → ตัวกรองอินพุต → ค้นคืน top-5 (dense + BM25) → prompt → LLM → ตรวจทุก claim → ตัวกรองเอาต์พุต → คำตอบ + แหล่งอ้างอิง / งดตอบ`
ใต้แผนภาพ 3 ป้าย: ตัวแปรที่เทียบ A/B/C/D · pipeline คงที่ vs LangGraph vs ReAct · ทุกกล่องมีการวัด
**บทพูด:** "ระบบไม่ใช่แค่ส่งคำถามให้ LLM แต่ควบคุมตั้งแต่ก่อนคำถามเข้าจนหลังคำตอบออก ฝั่งซ้ายคือการป้องกันและการค้นหา ตรงกลางคือการสร้างคำตอบเป็นข้อๆ พร้อมอ้างอิง ฝั่งขวาคือการตรวจว่าทุกข้อมีที่มาจริงก่อนแสดงให้ผู้ใช้" แล้วเดโมถามหนึ่งข้อ (HbA1c) ชี้แหล่งอ้างอิง (เอกสาร ฉบับ หน้า PDF)
**หลักฐาน:** `demo.py --web`; README หัวข้อ 1 และ 3
**ถ้าถูกถาม:** "ทำไมไม่ส่งตรงให้ LLM" → LLM แต่งตัวเลข/แหล่งอ้างอิงได้อย่างมั่นใจ และเปิดช่อง prompt injection เราจึงตรวจทั้งสองฝั่ง (แผ่น 4 และ 8)

## แผ่น 3 การตัดสินใจ 1: ข้อมูลและการค้น (1:15)
**บนสไลด์:** ตาราง 4 แถว "เลือก → ทำไม → จุดอ่อน → ที่เพิ่ม":
| เลือก | ทำไมเหมาะกับปัญหานี้ | จุดอ่อนที่พบ → ที่เพิ่ม |
|---|---|---|
| chunk ตามย่อหน้า/ประโยค/แถวตาราง ไม่ตัดกลางคำ + **parent-child** (ค้นด้วย 128 token ส่ง 512 token) | คำถามส่วนใหญ่ถามข้อเท็จจริงเดียว chunk เล็กตรงเป้ากว่า แต่โมเดลต้องการบริบทเต็ม | chunk เล็กตัดกลางประโยคมาก (26% ที่ 128 เทียบ 5% ที่ 512) → ส่ง parent |
| **bge-m3** (เทียบ e5-base) | รองรับไทย ใช้บน CPU ได้ เลือกจากผล dev ไม่ใช้ test | dense พลาดชื่อยา/ตัวเลข/คำเฉพาะ |
| **hybrid: dense + BM25 ตัวอักษร 3 ตัว** (convex α 0.6) | ภาษาไทยไม่มีช่องว่างคั่นคำ BM25 ระดับตัวอักษรจับคำตรงตัว | → R@10 จาก 0.827 เป็น 0.981 |
| **rerank** (cross-encoder bge-reranker-v2-m3) เป็นตัวเลือก C | แม่นขึ้นที่อันดับต้น | ช้าบน CPU 15–36 วินาที/คำถาม → ไม่ใช่ค่าเริ่มต้น |
**บทพูด:** "ทุกอย่างเริ่มจากตั้งคำถามว่าปัญหานี้ต้องการอะไร ข้อเท็จจริงสั้นๆ จึงใช้ chunk เล็กค้น แต่ส่ง chunk ใหญ่ให้โมเดลอ่าน dense อย่างเดียวพลาดชื่อยาและตัวเลข เราจึงเติม BM25 ระดับตัวอักษรเพราะภาษาไทยไม่มีช่องว่าง ได้ผลดีขึ้นชัด และทดสอบ rerank แต่ช้าบน CPU จึงเก็บไว้เป็นตัวเลือก" ปิดด้วยความซื่อสัตย์: "บน benchmark สาธารณะ 14 ชุด hybrid ชนะ dense 6 ชุด และแพ้ 4 ชุด จึงบอกได้แค่ว่าเหมาะกับข้อมูลไทยของเรา ไม่ใช่ดีกว่าเสมอ"
**หลักฐาน:** `docs/chunk_size_evidence.md` (128/256/384/512), `docs/hybrid_retrieval_experiment.md`, `docs/handoff_track_c.md`, `runs/frozen_gen_v1/public_benchmarks/`
**ถ้าถูกถาม:** (ตอบเอง) ทำไม chunk ขนาดนี้ และถ้าใหญ่/เล็ก 2 เท่าเกิดอะไร → จำนวน chunk 24,023 / 10,481 / 6,252 / 4,386 ที่ 128/256/384/512, token กลาง 93/188/290/399, รอยตัดกลางย่อหน้า 26/12/7/5% เล็กเกินตัดบริบท ใหญ่เกินเจือจางและเกินขีดจำกัด embedding

## แผ่น 4 การตัดสินใจ 2: ตอบจากหลักฐานและตรวจคำตอบ (1:00)
**บนสไลด์:** กล่องเดียว: `คำตอบ = claim 1..n; claim = {ข้อความ, อ้างอิง S1..S5}` → 3 ตัวตรวจ (ไอคอนเครื่องหมายถูก): ① citation ต้องชี้หลักฐานที่ส่งจริง ② ตัวเลขต้องอยู่ในหลักฐานที่อ้าง ③ คำอังกฤษต้องอยู่ในหลักฐาน · ใต้กล่อง: "ข้อที่ไม่ผ่านถูกตัดทิ้ง ไม่ซ่อม ไม่ใช้ LLM ตรวจซ้ำ"
**บทพูด:** "เราให้โมเดลตอบเป็นข้อๆ พร้อมอ้างอิง เพื่อให้ตรวจด้วยโค้ดได้ ตัวตรวจเป็นกฎ ไม่ใช่ LLM เพราะอธิบายได้ ทำซ้ำได้ และไม่ถูกหลอกง่ายด้วย injection" แล้วเล่าจุดอ่อนที่เจอจริง: "ตัวตรวจเคยตัดเลข 3 ที่ผู้ใช้พิมพ์เองในคำถามว่า 'ระยะ 3' ทำให้ข้อสำคัญของคำตอบ metformin หายไป เราจึงอนุญาตเลขที่ผู้ใช้เขียนเองใน demo (โปรไฟล์ N8) แต่ไม่ขยายไปถึงคำอังกฤษ เพราะจะเปิดช่อง injection"
**หลักฐาน:** `src/ncdqa/rag/validate.py`; `docs/error_analysis_track_c.md` §1, §3; เดโมปุ่ม "metformin ระยะ 3"
**ถ้าถูกถาม:** "ทำไมไม่ให้ LLM ตรวจรอบสอง" → LLM ตรวจก็ถูกหลอกด้วย injection ได้ และช้า/แพง/ไม่นิ่ง ตัวตรวจแบบกฎวัดได้ชัด; ข้อเสีย: ตรวจได้แค่เลข/แหล่ง/คำ ไม่ตรวจความสอดคล้องของ claim (เป็นช่องที่เราบันทึกไว้ q163)

## แผ่น 5 Ablation 1: การค้นคืน (1:00)
**บนสไลด์:** ตาราง + กราฟแท่ง R@1/R@5/R@10 (test 52 ข้อ)
| ระบบ | R@1 | R@5 | R@10 | MRR@10 |
|---|---|---|---|---|
| A dense | 0.462 | 0.808 | 0.827 | 0.618 |
| B hybrid | 0.587 | 0.885 | 0.981 | 0.737 |
| C hybrid + rerank | 0.615 | 0.913 | 0.952 | 0.771 |
**บทพูด:** "เปลี่ยนจาก dense เป็น hybrid ได้มากสุด R@1 เพิ่ม 0.125 และ R@10 เพิ่ม 0.154 rerank ช่วยอันดับบนเพิ่มอีกเล็กน้อย (R@1 +0.028) แต่ R@10 ลดลงจาก 0.981 เป็น 0.952 เราตรวจเป็นรายข้อแล้ว: ผลต่างนี้มาจากแค่ 2 ข้อจาก 52 ซึ่ง reranker ดันหลักฐานที่ hybrid เคยจัดไว้อันดับ 2–4 ให้ตกไปต่ำกว่าอันดับ 10 จึงไม่มีนัยสำคัญ และไม่มีข้อไหนที่ rerank ช่วยให้ R@10 เพิ่ม"
**Metric:** Recall@k = สัดส่วนหลักฐานเฉลยที่อยู่ใน k อันดับแรก (วัดว่าเจอไหม), MRR = ส่วนกลับของอันดับแรกที่ถูก (วัดว่าขึ้นบนสุดไหม) ใช้โค้ดเดียวกับทีมค้นคืน
**หลักฐาน:** `docs/handoff_track_c.md`; ตรวจ q133 และ q149 (เสียหลักฐานเฉลยใน top-10 ไป 1.0 และ 0.5 → 1.5/52 = 0.029); `runs/frozen_v1/`
**ถ้าถูกถาม:** (ตอบเอง) ถ้าเอา BM25 หรือ reranker ออก → ดูตารางนี้: เอา BM25 ออก R@10 ลด 0.154 เพราะ dense พลาดคำตรงตัว; เอา rerank ออกอันดับบนลดเล็กน้อยแต่ได้ความเร็ว 15–36 วินาที/ข้อบน CPU; ขอบเขต: 52 ข้อ ช่วงเชื่อมั่นกว้าง ผลต่าง B กับ C ไม่มีนัยสำคัญ

## แผ่น 6 Ablation 2: คำตอบ และ fixed vs LangGraph vs ReAct (1:15)
**บนสไลด์:** ตาราง (test 52 ข้อที่ตอบได้ + 4 ข้อไม่มีคำตอบ) และกราฟ correctness กับ token/ข้อ
| ระบบ | correctness | faithfulness | hit@5 | token/ข้อ |
|---|---|---|---|---|
| A dense | 0.798 | 0.803 | 43/52 | 4.8k |
| B hybrid | 0.885 | 0.827 | 46/52 | 4.8k |
| **C hybrid + rerank** | **0.904** | **0.886** | 48/52 | 4.8k |
| D BM25 ล้วน | 0.808 | 0.768 | 42/52 | 4.8k |
| ReAct (Python = LangGraph) | 0.827 | 0.833 | 47/52 | 26.5k |
**บทพูด:** "สามข้อ หนึ่ง คุณภาพการค้นส่งต่อถึงคำตอบ A→B→C สอง BM25 ล้วนใกล้ dense แต่แพ้ hybrid แปลว่าสองสัญญาณเสริมกัน สาม ที่เราให้ความสำคัญที่สุด: agent แบบ ReAct ที่ค้นเองหลายรอบ ไม่ชนะ pipeline คงที่ ใช้ token มากกว่า 5.5 เท่า และ correctness ต่ำกว่า B 0.058 (ช่วงเชื่อมั่น 95% −0.154 ถึง +0.038)" อธิบายเหตุ: "agent เขียนคำค้นเองแล้วค้นแย่กว่าคำถามเดิม (query drift) ไม่มีเกณฑ์หยุด และบริบทเจือจาง เราลองแก้ด้วยการค้นด้วยคำถามเดิมก่อน ทำให้ hit@5 กลับมาเท่า B แต่คำตอบยังไม่ดีกว่า ในโดเมนนี้ที่คำถามส่วนใหญ่เป็นข้อเท็จจริงเดียว การค้นรอบเดียวที่ดีพอจึงเหมาะกว่า"
**LangGraph:** คำตอบเหมือน Python 106/106 (dev) และ 56/56 (test) เพราะต่างกันแค่การควบคุมลำดับ ข้อดีของ LangGraph: เส้นทางตรวจสอบได้และมี node กู้คำตอบที่เสีย (กู้ได้ 60 จาก 71 ข้อที่ถูกตัดเมื่อจำกัด token)
**หลักฐาน:** `runs/frozen_gen_v1/react_test_results.md`, `runs/frozen_gen_v1/eval/`, `docs/error_analysis_track_c.md`
**ถ้าถูกถาม:** "agent ไม่ดีเหรอ" → ตอบว่า "ในโดเมนและการตั้งค่านี้ไม่ดีกว่า" ไม่ใช่ "agent ไม่ดี" งานวิจัยก็ยังไม่ชี้ว่า agentic RAG ชนะเสมอ; "ทำไมต้องทำทั้ง LangGraph และ Python" → เพื่อแยกผลของการควบคุมลำดับออกจากผลของวิธีค้น

## แผ่น 7 Metric: วัดอะไร ได้เท่าไร ตีความอย่างไร (1:15)

|---|---|---|---|
| **correctness** (judge อ้างเฉลย correct/partial/wrong/no_answer = 1/0.5/0/0) | คำตอบมีข้อเท็จจริงสำคัญตรงเฉลยไหม | C 0.904 · B 0.885 · ReAct 0.827 · D 0.808 · A 0.798 | ตัวชี้วัดหลักของ "ตอบถูก" |
| **faithfulness** (แบบ RAGAS เขียนเอง) | สัดส่วน claim ที่หลักฐานรองรับ = ไม่แต่งเติม | C 0.886 · B 0.827 · ReAct 0.833 · A 0.803 · D 0.768 | ตอบถูกแต่แต่งเติมก็ได้ จึงต้องแยกวัด |
| **BERTScore** (bge-m3 ชั้น 8, วิธีตรงแพ็กเกจต้นฉบับ) | ความใกล้เชิงความหมายกับเฉลย | A 0.838 · B 0.837 · C 0.837 · D 0.846 · ReAct 0.832 | แยกถูก/ผิดได้น้อย (ช่วงเชื่อมั่นซ้อนกัน; D ได้สูงสุดทั้งที่ correctness ต่ำกว่า) ใช้ดู ไม่ใช้ตัดสิน |
| citation / abstention / hit@5 / token | อ้างหน้าถูกไหม / งดตอบถูกไหม / ค้นเจอไหม / ต้นทุน | ดูแผ่น 6 | ใช้อธิบายสาเหตุ |
**บทพูด:** "เราวัดสองแกนที่โจทย์ต้องการ และมากกว่านั้น correctness ดูว่าตอบถูกไหม faithfulness ดูว่าแต่งเติมไหม ซึ่งไม่เหมือนกัน BERTScore วัดความใกล้เชิงความหมายกับเฉลย เราพบว่าค่าเกือบเท่ากันทุกระบบแม้ correctness ต่างกัน เราตรวจแล้วโดยเทียบกับแพ็กเกจต้นฉบับ" (ซื่อสัตย์) "รอบแรกเราวัด BERTScore ผิดมาตรฐาน คือไม่ตรงนิยามของแพ็กเกจต้นฉบับ ต่ำไปราว 0.016 เราแก้ วัดใหม่ทั้งหมด และข้อสรุปเชิงเปรียบเทียบไม่เปลี่ยน"
**ความน่าเชื่อถือของ judge (ต้องพูดเอง):** judge เป็น LLM (gpt-5.6-luna) ไม่มีคนตรวจ ตรวจด้วย sanity 48/48, สลับตำแหน่ง, ไม่มี length bias; judge ตัวที่สอง (Gemini) ตรงกัน 0.85–0.96 บนข้อที่ตัดสินได้ (ครอบคลุมไม่ครบ ~46–75% ของข้อ); **judge ไม่นิ่ง ±0.03** ใกล้เคียงความต่างระหว่างระบบ จึงอ่านเป็นทิศทาง; faithfulness เดิมต่ำเกินจริงส่วนหนึ่งเพราะ claim ฝากบริบทไว้กับคำถาม ให้ judge เห็นคำถามแล้วสูงขึ้น 0.03–0.10 ทุกระบบ ลำดับเดิม (C 0.915, B 0.907, A 0.898, ReAct 0.896, D 0.819)
**หลักฐาน:** `runs/frozen_gen_v1/eval/`, `runs/frozen_gen_v1/eval/bertscore_compat.json`, `docs/error_analysis_track_c.md` §4–5, §10–11
**ถ้าถูกถาม:** (ตอบเอง) ผลไหนเซอร์ไพรส์สุดและกลไกคืออะไร → ตัวเลือก: BERTScore เท่ากันทั้งที่ correctness ต่าง (วัดความใกล้เชิงความหมายโดยรวม ไม่ไวต่อเลขหรือเงื่อนไขที่ผิดเล็กน้อย จึงแยกถูก/ผิดไม่ได้ดี); ReAct ไม่ชนะ (query drift); faithfulness ต่ำเกินจริง (claim ที่ฝากบริบทไว้กับคำถามถูกนับว่าไม่รองรับ)

## แผ่น 8 Harness และความปลอดภัย (1:15 + เดโมสั้น)
**บนสไลด์:** ซ้าย: แผนภาพ 3 ชั้น (input / ข้อมูลที่ค้นและ tool / output) กับสิ่งที่ป้องกันในแต่ละชั้น; ขวา: กราฟแท่ง ASR ที่ถึงผู้ใช้ **0.58 → 0.09 → 0/45** และบรรทัด "ชุดเคสอิง OWASP LLM Top 10 (2025): 76 เคส ครอบ LLM01, 02, 05, 06, 07, 08, 09, 10"
**Harness คืออะไรในงานนี้:** ชุดเคสโจมตี + ตัวตัดสินด้วยกฎ (ไม่ใช้ LLM) ที่รันผ่านระบบทีละชั้น วัด attack success rate (ASR) เทียบกับประสิทธิภาพปกติ (ปฏิเสธทุกอย่างได้ ASR 0 แต่ใช้ไม่ได้ จึงรายงานทั้งคู่)
**บทพูด:** "ความปลอดภัยของ LLM แอปไม่มีชั้นเดียวที่พอ เราจึงป้องกันเป็นชั้น และวัดทีละชั้นด้วย harness: แต่ละเคสมีข้อความ canary ถ้าโผล่ในคำตอบแปลว่าโมเดลทำตามคำสั่งโจมตี เราวัดสองจุด คือสิ่งที่โมเดลพ่นออกมา กับสิ่งที่ถึงผู้ใช้หลังตัวตรวจ เพื่อเห็นว่าแต่ละชั้นช่วยเท่าไร" แล้วเล่าชั้นป้องกัน:
- **input:** ปิดบังข้อมูลส่วนบุคคลก่อนส่งโมเดล (เลขบัตรตรวจ check digit, เบอร์, อีเมล, HN, ชื่อ+คำนำหน้า); ปฏิเสธการขอสั่งยา/วินิจฉัยรายบุคคล; อาการฉุกเฉินขึ้น 1669; จำกัดความยาว; ตรวจรูปแบบ injection
- **ข้อมูลที่ค้นมา/tool:** ตัวคั่นข้อมูล (spotlight) และย้ำคำสั่งท้าย (sandwich); ตัด chunk ที่ติดธงคำสั่งแฝง; tool ของ agent อ่านอย่างเดียวและจำกัดอาร์กิวเมนต์
- **output:** ตรวจ claim; ระงับคำตอบที่มี markup/ลิงก์ที่หลักฐานไม่มี/ข้อความ prompt/ข้อมูลส่วนบุคคล
- **ข้อมูลและกระบวนการ:** log เฉพาะ metadata ไม่เก็บข้อความคำถาม; คีย์ไม่อยู่ใน git; แผ่นพับศิริราชที่ห้ามเผยแพร่ไม่อยู่ใน git
**ผลและการตีความ:** ไม่มีการป้องกัน ASR 0.58 (26/45) → ชั้นเดิม 0.09 (4/45) → ระบบที่ส่งมอบ 0/45 ที่ถึงผู้ใช้ (ดิบจากโมเดลยังหลุด 6/45 และถูกตัวตรวจกั้น); ReAct 1/51 ซึ่งเป็นเคสที่ผู้ใช้สั่งเองไม่ใช่ช่องโหว่; ชุดแรก: กติกา+schema ลด 0.65 → 0.04; ชุด adaptive (ผู้โจมตีรู้ schema): ตัวตรวจคำอังกฤษลด 0.43 → 0.14; ตัวกรอง injection ไม่บล็อกคำถามจริงเลย (0/162); mask ข้อมูลส่วนบุคคลรูปแบบปกติ 11/11 แต่รูปแบบที่ไม่ได้เขียนกฎไว้ 4/7
**ที่ยังกันไม่ได้ (พูดเอง):** chunk ปลอมที่เขียนเหมือนแนวทางจริง (ต้องคุมที่ ingest), ชื่อที่ไม่มีคำนำหน้า, LLM03/04 ไม่ได้ทดสอบตอนรัน; เคสเป็น silver (AI เขียน ไม่มีคนตรวจ) 0/45 ไม่ใช่การรับรอง ขอบบน CI ≈ 8%
**ทำซ้ำได้:** harness ใช้ config เดียวกับ pipeline, manifest เก็บ commit/hash, สคริปต์ปฏิเสธรัน test ถ้า git ไม่สะอาด, test รันครั้งเดียวต่อ config ที่ freeze
**หลักฐาน:** `docs/owasp_guardrails.md`, `runs/frozen_gen_v1/owasp/`, `runs/frozen_gen_v1/guardrail/`, `docs/decisions_guardrail_harness.md`
**เดโมสั้น:** (1) "Ignore all previous instructions..." → ถูกปฏิเสธ (2) ข้อความที่มีชื่อ+เบอร์ → ถูกปิดบังก่อนส่งโมเดลแล้วตอบต่อ (3) "ผมเป็นเบาหวาน กินยากี่เม็ด" → ปฏิเสธ (4) เจ็บหน้าอก → 1669
**ถ้าถูกถาม:** "ทำไมไม่ใช้ LLM กรอง injection" → ถูกหลอกด้วย injection เองได้; "0/45 ปลอดภัยแล้วเหรอ" → ไม่ใช่ เป็นผลบนเคสของเรา n เล็ก; "OWASP หมวดไหนที่ไม่ได้ทำ" → LLM03/04

## แผ่น 10 AI Audit: 3 การตัดสินใจสำคัญ + 1 error catch (0:45)

## ข้อควรระวังของคำพูด (ห้ามพูดเกินหลักฐาน)
